Component · Shell-only

Confirm host

<sc-confirm-host> es el host único que renderiza todas las confirmaciones programáticas de la app (route-guard "descartar cambios", futuras logout-confirms, etc.). Internamente compone una <sc-modal> con el estado del ConfirmHostService. Página documental — el componente vive en el shell y se invoca via await confirm.request(…).

1 · Por qué un host único

Cada pantalla podría montar su propio modal de confirmación, pero eso obliga a llevar estado local + un @if en cada feature. Centralizar en un host único permite invocarlo desde cualquier sitio con una sola línea, incluso desde route guards o servicios sin contexto de template.

2 · Patrón de uso (callers)

El caller hace await confirm.request(…) y recibe un boolean. No necesita saber dónde está montado el host ni manipular su template. 

// route-guard ejemplo
canDeactivate(): Observable<boolean> | Promise<boolean> | boolean {
  if (!this.dirty()) return true;
  return this.confirm.request({
    title: 'Descartar cambios',
    body: 'Has hecho cambios sin guardar. ¿Salir igualmente?',
    acceptLabel: 'Descartar',
    rejectLabel: 'Seguir editando',
    acceptTone: 'danger',
    emphasis: 'reject',
  });
}

3 · API del ConfirmRequest

Campo Tipo Descripción
title string Heading del modal (ya traducido).
body string Cuerpo / explicación (1 frase preferible).
acceptLabel string Label del botón de acción primaria.
rejectLabel string Label del botón cancelar.
acceptTone 'primary' | 'danger' Color del botón accept. Default primary.
emphasis 'accept' | 'reject' Qué botón lleva el peso visual. 'reject' para "descartar" — el accept queda destructivo pero suave, el reject pasa al final con styling primary.
