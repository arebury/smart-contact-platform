Component

Search

<sc-search> compone <p-iconfield> + <p-inputicon> + pInputText con icon overlay decorativo (vs p-inputgroup que es para addons con border merge). Encapsula el patrón .page__search que vivía duplicado en 6 SCSS distintos de AED list-pages. Soporta clear button automático y shortcut hint (⌘K, /).

1 · Básico

Icon search a la izquierda + input + clear button (×) cuando hay texto. showClear es true por defecto.

Valor: "{{ basicQuery() }}"

2 · Con shortcut hint (⌘K)

El shortcutHint aparece a la derecha cuando el campo está vacío y sin foco — pista de que existe un atajo global para enfocarlo. Desaparece al focus o cuando hay texto (para no robar atención del clear button). Patrón GitHub / Linear / Slack.

Valor: "{{ withHintQuery() }}"

3 · Picker dentro de sub-section (size sm)

Para search bars dentro de un picker / sub-section: size="sm" + sin shortcut hint (el atajo global lo gestiona el toolbar de página, no este campo). Caso real en AED: pickers "agendas" y "plantillas" dentro de agent-form.

Valor: "{{ pickerQuery() }}"

4 · Variant filled

Background slate-50, alineado con la variant filled de sc-input. Útil cuando el search vive sobre un fondo blanco y necesita más contraste.

5 · Con valor inicial (clear button visible)

El clear button (×) aparece automáticamente cuando value !== ''. Click → vacía el campo, emite valueChange, y foca el input para que el usuario siga escribiendo.

6 · API pública focus()

El componente expone un método focus() para que un atajo global del consumer enfoque el campo (típico en el listener ⌘K del shell). En el demo, el botón llama al método vía viewChild.

7 · (keydown) re-emit

El componente re-emite el KeyboardEvent del input para que el consumer maneje Esc, Enter, etc. sin tener que envolver el <sc-search> en un wrapper con (keydown).

Última tecla: @if (lastKey()) { {{ lastKey() }} } @else { (pulsa algo) }

8 · Reactive Forms

Soporta FormControl via ControlValueAccessor. Mismo binding que sc-input.

FormControl value: "{{ searchCtrl.value }}"
