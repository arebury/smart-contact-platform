01

Qué cambió

Hasta v1, el SCDS exponía cinco categorías primitive paralelas —spacing, font-size, line-height, icon-size, radius—, cada una con su propia escala numérica. El Kit Pro Figma SC, en cambio, usa una sola escala scale.* que sirve a todos los valores numéricos (padding, font-size, icon-size) más una escala dedicada border.radius.*. Esto generaba traducción mental cada vez que diseño y código hablaban de un mismo valor.

En v2 la primitive layer se reescribe para reflejar Kit Pro tal cual. El resto de categorías sobreviven como alias semantic-derived —preservan la API pública sin romper a los 1.127 consumers existentes—.

Antes · v1 5 primitives paralelos
  • --sc-spacing-50 / 100 / 900 Naming numérico custom SC
  • --sc-font-size-50 / 100 / 900 Valores propios decimales
  • --sc-line-height-50 / 100 / 900 Valores propios decimales
  • --sc-icon-size-xs / sm / md / 3xl Valores propios px literales
  • --sc-radius-0 / 50 / 500 Naming numérico custom SC
→
Después · v2 1 primitive + 1 escala dedicada
  • --sc-scale-0-25 / 0-5 / 5 Kit Pro scale.* verbatim · 34 entries
  • --sc-font-size-* alias → var(--sc-scale-*)
  • --sc-line-height-* alias → var(--sc-scale-*)
  • --sc-icon-size-* alias → var(--sc-scale-*)
  • --sc-radius-none / xs / sm / md / lg / xl Kit Pro border.radius.* verbatim
02

Por qué importa

  1. A

    Single source of truth numeric

    Cambiar --sc-scale-1 (14px → 16px) propaga automáticamente a font-size, padding e icon-size sin tocar consumers. La escala vive en un único sitio.

  2. B

    Mapping mecánico Figma ↔ código

    Cuando el equipo de diseño exporta design-tokens.json, el string scale.0-875 matchea directo con --sc-scale-0-875. Sin traducción, sin tabla de equivalencias mental.

  3. C

    API pública preservada

    Los 1.127 usos existentes de --sc-spacing-*, --sc-font-size-* y compañía siguen funcionando como aliases. Cero sweep cross-app, cero breaking para AED + Memory + ds-docs.

  4. D

    Blindaje upgrades upstream

    Cuando llegue PrimeOne 5.x con cambios en scale.*, el SCDS hereda sin refactor. La identidad SC vive en la collection Custom de Figma Variables —separada del primitive heredado—.

03

Tokens canonical en JSON

La primitive layer SCDS se exporta como sc-tokens.json en formato Design Tokens Community Group (DTCG). Cualquier dev de tercera app puede consumirlo sin clonar este monorepo —el JSON es el contrato de tokens versionado—.

Incluye la escala completa Kit Pro 1:1, las paletas brand SC (navy, electric-blue, amber) marcadas como $extensions.sc.custom, y los semantic-derived aliases para legibilidad humana.

Qué viene después

  • Próximo

    Convergencia color

    Alinear paletas brand SC (navy, electric-blue, amber) con la collection Custom de Figma Variables. Las paletas permanecen custom-named —no se renombran a Aura— pero quedan documentadas en el JSON.

  • Pendiente

    Spec session equipo de diseño

    Seis items dormidos esperan decisión externa: sc-search clear icon, page__inner max-width canonical, sm/md/lg variants form wrappers, shadows sticky-footer-top y drag-hover, escala duration en Variables.

  • Futuro

    Memory como primer consumer externo

    Cuando Memory entre desarrollo activo post-v2, consumirá el JSON como source-of-truth. Validará el contrato canonical en un consumer real fuera del monorepo Angular.
