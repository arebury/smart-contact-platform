# Smart Contact Platform — design context

## Design Context

### Users

Tres audiencias del monorepo Smart Contact:

- **Designers (Marta)** — PM/designer non-dev. Lee specs, valida visualmente, compara
  con Figma Smart Contact Prime. Necesita comodidad lectora + screenshots claros + ZIP
  shareables.
- **Devs internos** — implementan features de AED / Memory. Consultan el catálogo SCDS
  para reusar componentes en lugar de re-inventar. Quieren ver API + tokens + recipes de
  migración rápido.
- **Rafael (founder, non-dev)** — orquesta el cocinado componente a componente.
  Habla castellano (España, tú), no dev background, valora tracking visual (checklist
  localStorage en la home) y claridad sobre qué falta vs qué está hecho.

Contexto de uso: desktop principalmente (1280-1440px), navegadores modernos, dark mode
default (audiencia técnica + documentación se consume en oficina/sesión larga).

### Brand Personality

3 palabras: **calmado, intencional, editorial** (NO "modern / elegant / clean" —
categorías muertas).

Tono: como una guía de estilo de un periódico cultural — texto técnico tratado con
seriedad, jerarquía clara, sin AI slop. No es startup con personalidad maximalist; no es
corporate genérico. Es Polaris × Wise × Stripe Press × una pizca de Linear.

Brand primary = **navy `--sc-color-blue-500` (#344a70)**. Accent vibrante = **electric-blue
`--sc-color-electric-blue-500` (#1464fe)** — usado para focus rings, dot accents, hover
state del primary. Slate complementaria (Aura) en gris.

### Aesthetic Direction

**Swiss Modernism + dark-mode-first**, ya validado en sesión 30 vía `/ui-ux-pro-max`.

- Fuentes APROBADAS (no cambiar) — establecidas y consumidas en producción hoy:
  - Display: **Space Grotesk** (h1, h2, brand)
  - Body: **Inter** (párrafos, labels, UI text)
  - Mono: **JetBrains Mono** (tokens, números, eyebrows, technical labels)
- Theme: dark default (audit page) + light mode también (gallery pages funcionan ambos
  vía `--sc-color-*` que cambian con `.sc-dark` en `<html>`).
- Layout: 12-col grid mathematical spacing, asymmetric breaks intencionados.
- Single accent (electric-blue) — no rainbow ni gradient text.
- Decoración mínima: dot accent pulsante, mono labels, accent rails de 3px en active
  states. NO border-left de 4px+ (prohibido), NO glassmorphism, NO sparklines, NO modals
  innecesarios.

Refs positivas: Polaris, Stripe Press, Wise design hub, Linear changelog, Vercel docs.
Anti-refs: typical Tailwind landing template, "futuristic SaaS" gradient hero, generic
admin dashboard sidebar.

### Design Principles

1. **Honest token math** — decimales raw (10.5px, 12.25px) si el Figma lo dice; no
   redondear "por limpieza". Memoria `feedback_figma_specs_thorough.md`.
2. **Single accent, used sparingly** — electric-blue solo para focus, dot accent,
   active state. El resto es slate/navy.
3. **Mono carries technical weight** — JetBrains Mono identifica todo lo "código /
   spec / número" — eyebrows, tokens, counters, numbered items.
4. **No layout shift** — galleries reservan altura, helpers/error min-height 1.25em,
   no-CLS verificado.
5. **Editorial spacing rhythm** — varied gap (no padding uniforme). Heading con más
   aire arriba; densidad apretada solo en sidebar / nav.
6. **Body slot stackeable** en componentes contenedor (modal, section card) — children
   directos apilados auto con gap consistente.

### CRITICAL — Scope of "polish" / "improve" requests

Cuando Rafa pida "mejorar / polish / refactor visual", aplica a:

✅ **ds-docs** (sitio de documentación): hero, sidebar, gallery wrapper, code blocks,
status strips, page chrome, micro-interactions.
✅ **Audit pages** (`apps/ds-docs/public/audits/*.html`): standalone artifact pages.
✅ **App shells y surfaces** que NO son componentes: nav, layout, header bar.

❌ **NUNCA** tocar:
- Componentes del catálogo SCDS (`packages/design-system/components/*`) — son
  interpretaciones honestas 1:1 de los tokens Figma. Su chrome NO se altera por
  "polish estético".
- Tokens (`packages/design-system/tokens/layers/*.css`) — son la fuente de verdad.
- `sc-preset.ts` — bridge a PrimeNG, también sagrado.
- Componentes consumidos por AED (`apps/supervisor/src/app/shared/components/*` que pasaron
  por audit Figma).

La diferencia: ds-docs es el VEHÍCULO de comunicación; los componentes son el
PRODUCTO. Polish va al vehículo. El producto solo cambia cuando una Figma audit lo
dicta.

### Tech constraints

- Angular 21 + SCSS (NO Tailwind).
- `--sc-*` tokens en 7 capas CSS (primitive → semantic → palette → component →
  extensions → dark). Componentes consumen via `var(--sc-*)`.
- PrimeNG + sc-preset bridge (`packages/design-system/tokens/sc-preset.ts`).
- Lucide icons (no emojis, no PrimeIcons salvo dentro de p-button).
- A11y AA mínimo: focus-visible rings, aria-* correcto, prefers-reduced-motion respect.
- Performance: lazy chunks routes (Angular standalone defer), no oversized fonts.
- Encoding: UTF-8 (cuidado con caracteres especiales en Edit/Write — usar Spanish
  copy-paste atómicos pequeños).
